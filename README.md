# GeoCheck AI

## Завершение рабочего цикла — 19 ноября 2026

Каталог принимает до 20 LAS/CSV за один выбор (по 10 МиБ каждый). Файлы обрабатываются последовательно, ошибка одного не отменяет остальные; результат каждого виден на экране. До выбора файлов задайте тип данных и необязательную ссылку источника. Импортированные файлы не считаются автоматически достоверными промысловыми измерениями. Известные точные копии синтетических файлов сохраняют соответствующую маркировку.

В отчётах появился **паспорт проверки**: доля отсчётов с предупреждениями без двойного счёта пересечений, пропуски в выбранных каналах, результаты методов, экспертные решения и следующие действия. Это вычисляемая сводка, не языковой ИИ. SHA-256 позволяет сверить исходный файл. Паспорт скачивается в TXT, CSV включает номера замечаний, решения, комментарии и даты. JSON содержит паспорт, графические данные и все исходные результаты анализа. Экспорт отражает текущие экспертные отметки, поэтому сохраняйте скачанный отчёт, если нужен неизменный снимок заключения.

Новый API: `GET /api/reports/{id}/summary`. Импорт принимает `source=upload|synthetic`. Новая рабочая база запускается пустой; демонстрационный набор добавляется только кнопкой «Восстановить демо». Существующие базы не очищаются.

Проверено: 16 Pytest, 3 Vitest, TypeScript/Vite; браузерные сценарии и сравнение с отраслевыми платформами описаны в [рабочем цикле](docs/workflow.md). Оформление вынесено в `frontend/src/workspace-theme.css`.

## Версия 2.0 — рабочая область и сохранённые модели

Обновлённый интерфейс объединяет каротаж и проверку замечаний на одном экране. Выберите скважину слева, запустите проверку, нажмите на интервал в таблице и подтвердите или отклоните замечание с комментарием. Решения сохраняются по конкретному запуску и входят в JSON-отчёт.

Раздел «Модели и обучение» создаёт настоящую сохранённую модель Isolation Forest. Выберите скважины для обучения и отдельные скважины для проверки, общие каналы с одинаковыми единицами и параметры леса. После расчёта модель, предобработка, паспорт выборки и результаты проверки сохраняются в SQLite. В анализе новой скважины выберите эту модель в списке методов. Кнопка «Восстановить демо» добавляет отсутствующие демонстрационные скважины и разметку, повторное нажатие переиспользует существующие записи.

В комплекте есть две чистые синтетические скважины GeoLab-Train-117 и GeoLab-Train-118 для обучения и GeoLab-01 с искусственными изменениями для проверки. Набор создаётся локально через восстановление демо. Источники КМГ перечислены в разделе «Источники данных», результаты поиска описаны в [обзоре открытых материалов](docs/public-sources.md). Подключённого набора каротажа КМГ сейчас нет.

Новые API — POST /api/demo/restore, GET /api/models, POST /api/models/train, GET /api/models/{id}, GET /api/analysis/{id}/reviews и PUT /api/analysis/{id}/reviews/{index}. POST /api/analysis/run принимает необязательный trained_model_id. Импорт файла принимает необязательное поле source_url. В production сохраняются модели как локальные артефакты joblib, загрузка внешних сериализованных Python-моделей не предусмотрена.

Локальная инженерная рабочая станция для контроля качества скважинного каротажа. Независимый студенческий проект для хакатона 2026 года. Загрузка пользовательских файлов, анализ и обучение выполняются реально; промышленная валидация пока не проведена. Все вычисления и хранение выполняются на компьютере.

## Запуск на подготовленном компьютере

Откройте `Start-GeoCheck.cmd` и перейдите в [GeoCheck AI](http://127.0.0.1:8000). Окно сервера должно оставаться открытым. Остановка — Ctrl+C. [Swagger UI](http://127.0.0.1:8000/docs) показывает контракт API. Автономное машинное описание доступно по `/openapi.json`. Swagger UI по умолчанию загружает свои ресурсы из CDN. Основной интерфейс использует локальную сборку.

## Установка с нуля в Windows

Нужны Python 3.12 x64 с pip, Node.js 22.12+ или 24 и npm. В PowerShell из корня проекта выполните команды ниже. Для первой установки пакетов нужен интернет.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements-lock.txt
npm.cmd ci --prefix frontend
npm.cmd run build --prefix frontend
.\Start-GeoCheck.cmd
```

Если Python доступен командой `python`, используйте `python -m venv .venv` для первого шага. При переносе на другой компьютер создайте окружение заново. Файл `requirements.txt` задаёт допустимые диапазоны при обновлении зависимостей, lock-файл фиксирует проверенные версии Windows.

## Сценарий работы

1. В обзоре выберите скважину в боковой панели. Число предупреждений в верхней карточке суммирует последние проверки по всем скважинам.
2. В «Данные скважин» загрузите LAS или CSV. Откройте строки таблицы, переключите колонки, при необходимости скачайте исходник. Оригинальные байты хранятся в SQLite. Удаление скважины с её отчётами требует подтверждения.
3. В «Каротаж» включите нужные треки, задайте интервал глубин или выделите область мышью. Все треки используют общую вертикальную шкалу. Подсветка берётся из последней сохранённой проверки выбранного файла.
4. В «Контроль качества» выберите признаки, методы, порог MAD, число деревьев и долю выбросов IF. Запуск сохраняет настройки, версии, оценки и интервалы. В таблице доступны причины и максимальный score IF по интервалу.
5. В «Отчёты» откройте нужный запуск. JSON содержит весь результат, включая отсчёты графиков, единицы и построчные scores. CSV содержит таблицу интервалов. Количество предупреждений считает группы соседних строк отдельно по методу и каналу: одно измерение может попасть в несколько групп.

## Структура

```text
frontend/

  src/pages/              импорт, каротаж, анализ, отчёты

  app/main.py             HTTP API, транзакции и раздача сборки
  app/storage.py          модели SQLite / SQLAlchemy
  app/ingest.py           парсеры LAS и CSV
  app/ml.py               правила, предобработка и Isolation Forest
  app/modules.py          контракт и реестр вычислительных модулей
  app/schemas.py          схемы запроса и результата
  app/demo.py             генератор синтетических скважин
  evaluate.py             независимая оценка на отложенной скважине

  tests/                  проверки алгоритмов, файлов и API

docs/                     методика и ограничения
runtime/                  локальная БД, создаётся автоматически
```

## Разработка и тестирование

Откройте корневую папку в VS Code. Через **Python: Select Interpreter** выберите `.venv\Scripts\python.exe`. Для разработки запустите два терминала PowerShell.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

```powershell
npm.cmd run dev --prefix frontend
```

Интерфейс разработки доступен на [порту 5173](http://127.0.0.1:5173). Vite проксирует запросы на порт 8000. После изменений для обычного запуска повторите сборку frontend. При переносе хранилища задайте переменную среды `GEOCHECK_HOME` до запуска. Для резервной копии остановите сервер и скопируйте `runtime/geocheck.sqlite`.

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests -q
npm.cmd test --prefix frontend
npm.cmd run build --prefix frontend
.\.venv\Scripts\python.exe backend/evaluate.py
```

Чтобы подключить вычисления к другому сервису, используйте REST или импортируйте модуль `app.modules` при добавленном в путь Python каталоге `backend`. Объект модуля содержит id, название, описание, Pydantic-схемы и функцию compute. Добавьте сервис нового модуля и зарегистрируйте его в REGISTRY, затем подключите его отдельный API/экран. Текущий endpoint анализа запускает well-log-qc.

### Проверенный результат в Windows

Для версии 2.0 прошли 14 тестов Pytest и 3 теста Vitest / React Testing Library. Сборка TypeScript и Vite завершилась успешно. В Microsoft Edge через Playwright проверены восстановление демо, обучение и оценка модели, применение сохранённой версии, решение эксперта с комментарием, его сохранность после обновления страницы, переход к глубине замечания, отчёт и скачивание JSON, импорт CSV со ссылкой на источник. На ширине 390 пикселей проверены мобильная навигация и отсутствие горизонтального переполнения шести страниц. Также тестируется повторное применение модели после пересоздания backend-приложения с той же БД.

В процессе тестирования Starlette предупредил о будущей смене библиотеки HTTP-клиента тестов. Vite сообщил о размере JavaScript-сборки с Plotly. Оба сообщения позволяют завершить проверки и запуск.

## Подготовка к GitHub

В корне уже есть .gitignore для рабочего окружения, локальных баз, кэшей и сборки. В репозиторий включайте исходники, оба lock-файла, документацию и разрешённые синтетические fixtures. Проверьте подготовленные изменения перед первым коммитом.

```powershell
git init
git add README.md .gitignore Start-GeoCheck.cmd backend frontend data docs
git diff --cached --stat
git commit -m "Add local GeoCheck AI workstation"

```

Создайте пустой репозиторий в своём аккаунте GitHub. Замените адрес ниже на его URL и выполните команды, когда будете готовы опубликовать исходники.

```powershell
git remote add origin https://github.com/YOUR-ACCOUNT/YOUR-REPOSITORY.git
git push -u origin main
```

## Границы применения и дальнейшее развитие

Текущая версия рассчитана на локальную работу одного пользователя. Один файл представляет одну скважину. Лимит составляет 10 МиБ, 50 000 строк и 64 канала, для одного анализа выбирают до 32 каналов. Эксперимент обучения ограничен 500 000 строк и 30 скважинами в каждой выборке. Вычисления синхронные и выполняются в серверном пуле потоков. История сохраняет версии алгоритмов, параметры и результаты. Модели из раздела обучения сохраняются в базе, разовая проверка скважины обучает временный лес. Параметры оформления находятся в `frontend/src/styles.css`. Шрифты Inter и IBM Plex Mono включены локально вместе с лицензиями OFL.

Следующие направления разработки — обучение классификатора на полной экспертной разметке, словарь кривых и преобразований единиц, проверка на промысловых скважинах, очередь длительных задач, восстановление пропусков, классификация литологии и выравнивание глубины. Текущие экспертные решения служат для разбора предупреждений и отчётности. Isolation Forest обучается без меток. Методика и результат проверки приведены в [описании анализа](docs/analysis.md), формат входных данных — в [памятке по данным](data/README.md).
